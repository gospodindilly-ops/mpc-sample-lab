# MPC Sample (AC50): звук и экран

Источники: DT из `kernel.fit` прошивки 1.3.0.12 ([`tools/dtdump.py`](../tools/dtdump.py)), rootfs, бинарь `MPC Sample`.
Живое состояние снято только чтением при работающем `ac50`: [`recon/audio-display-ro-20261022.txt`](../recon/audio-display-ro-20261022.txt).
Пометки: **[DT]**, **[rootfs]**, **[живое]** — подтверждено; **[гипотеза]** — требует проверки.

## 1. Звук

### Аппаратный тракт **[DT]**
```
I2S-TDM контроллер i2s@fe410000 (master BCLK/LRCK, mclk = 512·fs)
        │ I2S
AK4558 (i2c@fe5b0000, адрес 0x10; питание analog-pwr, PDN-GPIO)
  DAC L/R → LOUT/ROUT ─┬→ Mute (GPIO, mute 50 мс / unmute 1000 мс) ─┬→ Headphones (детект GPIO3_B0)
                        │                                             └→ Line Out Jack (детект GPIO3_B1)
                        └→ Speaker amp (GPIO) → Builtin Speaker
  ADC L/R ← LIN/RIN ←─┬─ Line Input amp «TRS» (GPIO)
                       └─ Internal Mic amp (GPIO + vdd-mic)
```
- Карта ALSA `simple-audio-card` «I2S», формат i2s, **частота зафиксирована на 44 100 Гц** (`convert-rate`).
- Переключатели DAPM: `Builtin Speaker`, `Builtin Microphone`, `TRS`. Детекторы джеков видны как устройства ввода «I2S Headphones» и «I2S Line Out Jack».
- `asound.conf` и UCM нет **[rootfs]**: приложение открывает устройства `hw:` напрямую. `amixer` на устройстве нет.

### Как его использует штатное приложение **[живое]**
| Карта | Направление | Формат | Каналы | Частота | period / buffer |
|---|---|---|---|---|---|
| I2S | playback | S32_LE | 2 | 44 100 | 128 / 384 кадров (2,9 / 8,7 мс) |
| I2S | capture | S32_LE | 2 | 44 100 | 128 / 256 |
| UAC2Gadget (USB-аудио к компьютеру) | play / capture | S32_LE | 2 | 44 100 | 24 / 384 |

Строка журнала `Audio 44100Hz; 4-in; 4-out; 128sample buffer` — это I2S 2 канала плюс USB 2 канала. В бинаре есть `Failed to set S32_LE format for …`.
Номер карты меняется между загрузками, поэтому искать её нужно по `/dev/snd/by-path/platform-sound`: эта строка есть в бинаре приложения.

### ALSA-контролы карты I2S **[rootfs + бинарь приложения]**
Источник имён — строки модулей ядра и `.rodata` приложения. Логика — дизассемблирование `MPC Sample`.

| Контрол | Откуда | Тип | Кто управляет |
|---|---|---|---|
| `Builtin Speaker Switch` | `pin-switches` в simple-card (`<pin> Switch`) | bool | приложение |
| `Builtin Microphone Switch` | то же | bool | приложение |
| `TRS Switch` (линейный вход) | то же | bool | приложение |
| `Headphones Jack`, `Line Out Jack` | детекторы джеков simple-card (`hp-det` / `out-det` GPIO) | bool, только чтение | ядро; приложение читает |
| `Playback Volume` | AK4558 (драйвер inMusic) | int | **никто**: приложение его не использует, громкость, видимо, программная **[гипотеза]** |
| `Playback Deemphasis`, `Playback Digital Filter`, `Capture Digital Filter`, `Capture HPF`, `Playback Attentuation Transition Time` | AK4558 | enum/bool | никто |

У усилителей (`simple-audio-amplifier`: Speaker, Line Input, Internal Mic) и у глушилки (`simple-audio-mute`) своих контролов нет. Их GPIO включает DAPM, когда тракт активен. У глушилки **задержка снятия 1000 мс**, поэтому поток PCM лучше держать открытым постоянно, а не открывать на каждую ноту. Сохранённого состояния микшера в rootfs нет: ни `alsactl`, ни `asound.state`.

**Политика приложения** (функция `0x14EA4D0`; запись значения — единственный вызов `snd_ctl_elem_value_set_boolean` + `snd_ctl_elem_write` в `0x23E6030`):
- **Источник входа** (настройка, значения 0–3):
  - 1 → `Builtin Microphone Switch` = 1, `TRS Switch` = 0;
  - 2 → `TRS Switch` = 1, `Builtin Microphone Switch` = 0;
  - 0 и 3 → оба выключены.
- **`Builtin Speaker Switch` = 1** только если **не вставлены ни наушники, ни линейный выход**, и при этом не выполнено «вход = встроенный микрофон и включена настройка против обратной связи» (строка `Disable Internal Mic While Speaker Is On`).
- **Наушники и линейный выход** отдельно не переключаются: их пины DAPM включает и выключает само ядро по детекторам джеков.

**Что это значит для своего приложения:** после остановки ac50 значения контролов остаются такими, какими их оставило приложение, потому что ядро их хранит **[гипотеза]**. Чтобы управлять динамиком самостоятельно, достаточно записать `Builtin Speaker Switch` (bool) через ALSA control API (`/dev/snd/controlC<N>`).

## 2. Экран

### Аппаратура **[DT, живое]**
- **SPI-дисплей**, а не RGB/MIPI. Его подключение описано в `spi@fe640000/display@0`, `compatible = vitek,vt024k-zn01`. Ядро привязывает к нему **DRM-драйвер `st7796s`** (контроллер Sitronix ST7796S, основа `drm_mipi_dbi`), устройство `spi3.0`.
- SPI до **25 МГц**, линия D/C — GPIO3_A7, сброс — GPIO3_A6, в DT задан поворот 270°.
- **Режим 320×240**, коннектор `SPI-1`, плоскость в формате **XR24 (XRGB8888)**, stride 1280.
- **fbdev-эмуляция:** `/dev/fb0` «st7796sdrmfb», 320×240, 32 бит/пиксель.
- **Подсветка:** `pwm-backlight`, уровни 0, 8, 16, 32, 64, 128, 255 (индексы 0–6). Сейчас 6 из 6.
- **GPU и VOP в DT отключены.** Значит, рисование только программное. Приложение рисует на CPU (буфер выделен «JUCE Message Thread») и держит `/dev/video0` = `rockchip-rga`, 2D-ускоритель, видимо для копирования и преобразования **[гипотеза]**.
- **Предел скорости:** кадр 320×240 при 16 бит на пиксель по SPI 25 МГц даёт около **20 кадров/с** на полный экран **[гипотеза: панель в RGB565]**.

### Кто держит экран **[живое]**
`az0x-splash` (PID 111): `/dev/dri/card0` и `/dev/fb0`; `MPC Sample`: `/dev/dri/card0` и `/dev/video0`.

## 4. Первый тест на устройстве (2026-10-22, `sound-test`, ac50 остановлен)

Журнал: [`captures/sound-test-run1-20261022.txt`](../captures/sound-test-run1-20261022.txt).
- **Переключатели после остановки ac50:** `Builtin Speaker Switch` on, `Builtin Microphone Switch` off, `TRS Switch` off, джеков нет. Ядро сохраняет состояние, оставленное приложением.
- **Звук работает:** I2S открывается с параметрами приложения (S32_LE, 2 канала, 44 100, 128 × 3), поток `RUNNING`, без потерь данных. 83 удара по всем 16 пэдам за 37 с. Владелец подтвердил, что тоны и цвета пэдов были такими, как задумано.
- **Экран оставался чёрным,** хотя `/dev/fb0` открылся и запись прошла без ошибок. Список DRM-клиентов (`/sys/kernel/debug/dri/0/clients`) показывает: master — `MPC Sample`, `az0x-splash` — клиент без прав master, у которого свои framebuffer'ы, а fbdev — это fb 37 «[fbcon]». Когда ac50 закрывается, его framebuffer'ы удаляются и плоскость гаснет. При этом `az0x-splash` держит устройство открытым, поэтому не наступает последнее закрытие, и ядро не возвращает fbdev на экран. Значит, `/dev/fb0` пишется в буфер, которого не видно **[вывод из состояния DRM]**.
- **Решение:** рисовать через DRM напрямую. Создать dumb-буфер, `ADDFB2` XR24, `SETCRTC` (коннектор 32, CRTC 35, режим 320×240), и после каждого рисования вызывать **`DIRTYFB`**: SPI-панели mipi-dbi обновляются только по сигналу damage. Если master окажется занят, `SETCRTC` вернёт `EACCES` **[проверить]**.

### Второй запуск: вывод через DRM (журнал [`captures/sound-test-run2-drm-20261022.txt`](../captures/sound-test-run2-drm-20261022.txt))
- `drm 320x240 crtc 35 connector 32 fb 41 pitch 1280`, без ошибок. После остановки ac50 тест стал DRM master (`az0x-splash` остался без master), и плоскость показывает буфер теста.
- **Экран работает:** видна сетка 4×4, клетки окрашиваются как пэды, ориентация правильная (поворот 270° делает драйвер). Подтверждено владельцем и фото.
- **Проблема: 20 потерь звука (underrun) на 20 ударов.** `DIRTYFB` на весь экран выполняет передачу по SPI внутри ioctl. Это 320×240 по 25 МГц, порядка 50 мс, а это больше буфера звука 8,7 мс. Поэтому однопоточный цикл теряет звук при каждой перерисовке. В первом запуске через fbdev, без `DIRTYFB`, потерь не было.
- **Что делать:** перерисовку экрана нельзя выполнять в звуковом цикле. Обновлять только изменённую клетку (клип 80×60, около 1/16 кадра) и вызывать `DIRTYFB` из отдельного потока.

### Третий запуск: поток экрана и клипы клеток (журнал [`captures/sound-test-run3-thread-20261022.txt`](../captures/sound-test-run3-thread-20261022.txt))
- Звуковой цикл только рисует клетку в буфер и ставит бит в маске. Отдельный поток отправляет `DIRTYFB` с прямоугольником на каждую изменённую клетку.
- **77 ударов по всем 16 пэдам за 26 с, в том числе одновременные: 0 потерь звука, 0 ошибок DRM.** Проблема второго запуска устранена.
- Правило для своих приложений: **звуковой поток никогда не ждёт SPI-дисплей.**

## 5. Что не проверено
- Текущие **значения** ALSA-контролов: на устройстве нет `amixer`. Имена и логика установлены офлайн (§1).
- Формат пикселя на шине SPI (RGB565 или RGB666) и реальная частота кадров.
- Поведение `/dev/fb0` и звука при остановленном ac50.
